# Свежесть данных агрегатора: авто-обновление вакансий

Дата: 2026-08-21
Статус: одобрено, в реализации

## Контекст

Агрегатор — статичный снапшот из 21 вакансии (15 из трёх Telegram-каналов, извлечённых
вручную мной в сессии, + 6 Architect-вакансий с Djinni, добавленных вручную). Данные
протухают, структурирование сырых постов не автоматизировано.

## Критерии

Пользователь: не сужать по ролям (все категории ROLE_ORDER нужны), главный фильтр —
**удалёнка**. Запуск обновления — вручную, одна команда, без cron (добавим позже, если
понадобится).

## Схема: новое поле `posted_at`

Экспайр требует знать возраст вакансии — сейчас в схеме такого поля нет. Добавляю
`posted_at: string | null` (ISO-дата поста в Telegram) в `Vacancy`:
`data/vacancies.json`, `src/modules/aggregator/vacancy.ts`, `backend/app/models.py`,
`src/modules/aggregator/vacancies.sample.json`. Для 6 вручную добавленных Djinni-вакансий
(нет скрейп-источника, чтобы их обновлять) — `posted_at: null`, экспайр их не трогает.

## `scraper/refresh_vacancies.py` (новый, одна команда)

1. Скрейпит `CHANNELS` (переиспользует `fetch_channel` из `fetch_telegram.py`) → сырые
   посты с датой.
2. Новые посты (дедуп по `id = f"{channel}/{post_id}"` против уже сохранённых в
   `data/vacancies.json`) — структурирует через headless `claude -p ... --model haiku
   --output-format json --safe-mode --tools "" --no-session-persistence` (та же
   изоляция, что в sub-project B, иначе CLI путает промпт с этой самой сессией).
   Промпт: текст поста → JSON по схеме `Vacancy` (без `id`/`url`/`source_channel`/
   `posted_at` — их проставляет скрипт из метаданных поста), или `{"skip": true}`, если
   пост не вакансия (реклама, шум, репост не по теме). Автоматизирует то, что раньше
   делал вручную.
3. Мёржит новые структурированные записи с существующими (upsert по `id`).
4. Фильтр: оставляет только `remote == true`.
5. Экспайр: `posted_at` старше `MAX_AGE_DAYS = 21` — дропает. Записи с `posted_at is
   None` (ручные, не-Telegram) экспайр не трогает.
6. Пишет результат в `data/vacancies.json` (source of truth) и зеркалит в
   `src/modules/aggregator/vacancies.sample.json` (бандл фронта).
7. Best-effort `POST http://localhost:8000/vacancies/import` — бэк не поднят, скрипт не
   падает, просто печатает предупреждение и продолжает (обновление не должно требовать
   запущенного бэка).

Извлечение — небольшая самостоятельная функция внутри скрипта (не импорт из
`backend/app/tailoring.py`): разные venv у `scraper/` и `backend/`, тащить кросс-пакетную
зависимость ради ~25 строк не стоит.

## Что не входит

- Cron/launchd-автозапуск — вручную, одна команда, по требованию пользователя.
- Сужение по ролям — только remote-фильтр.
- Новые источники каналов — тот же список из трёх, пересмотр списка не запрошен.
