# Sub-project C: PDF-рендер финального тейлоренного резюме

Дата: 2026-08-21
Статус: одобрено, в реализации

## Контекст

A (галерея+approve на моке) и B (реальный тейлоринг через Claude Code CLI, Haiku+Sonnet,
подключён к фронту) готовы. C — последний из трёх подпроектов пайплайна генерации:
превратить `TailoredResume` (то, что approve-страница уже показывает) в скачиваемый PDF.

## Подход

`@react-pdf/renderer` (MIT, npm) — компонует PDF из React-компонентов прямо в браузере.
Никакого бэкенда: PDF собирается из тех же данных, что уже отрендерены на approve-странице,
без лишнего сетевого раунд-трипа и без второй копии рендер-логики на Python.

Отклонённые варианты: встраивание целого опенсорс-конструктора (Reactive-Resume/Open-Resume)
— тяжеловесно, чужой стек ради шаблона; бэкенд-рендер (reportlab/weasyprint) — лишняя
зависимость и роут, дублирует то, что уже есть на фронте.

## Компоненты

**`src/modules/pipeline/review/resumeText.ts`** (новый) — `currentPlainText(resume:
TailoredResume)`, вынесен из `ApproveViewPage.tsx` (сейчас там inline-функция), чтобы не
дублировать между черновиком редактирования и PDF-экспортом. Возвращает `{summary: string,
experience: string[], skills: string[]}` — финальный текст (unchanged+added, без removed).

**`src/modules/pipeline/review/ResumePdfDocument.tsx`** (новый) — `<ResumeDocument
plain={...} candidateName={...} vacancyTitle={...} company={...} />`, ATS-safe лейаут:
Helvetica, чёрный текст на белом, без цвета диффа (PDF — всегда финальная версия, не диф).

**`ApproveViewPage.tsx`** — кнопка "Скачать PDF" рядом с тумблером тейлоренное/оригинал.
Активна только когда `resume` загружен и `mode === 'tailored'` (PDF — не для
original-режима, там просто сравнение). Клик: `pdf(<ResumeDocument .../>).toBlob()` →
временная ссылка → скачивание, имя файла `<имя резюме> — <название вакансии>.pdf`
(санитизированное).

## Что не входит в C

- Несколько шаблонов/тем — один чистый ATS-safe лейаут.
- Пакетное скачивание всех N резюме зараз (zip) — только по одному с approve-страницы.
- Cover letter в PDF — отдельно не рендерим, `cover_letter_path` в модели не используется.
